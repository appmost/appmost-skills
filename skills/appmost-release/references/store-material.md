# Store material and release readiness

## Build an accurate story

Describe the app's user benefit and actual available functionality. Keep titles, descriptions, release notes and review notes consistent with the selected build. Localize copy for the intended store locales and review it in context.

Capture the real app in meaningful populated and relevant alternate states, using synthetic demonstration data. Show the requested platform and device accurately. A contact sheet helps review coverage, but final images need individual inspection for text, crop, hardware/frame fidelity and private information.

Use app-owned export/rendering tools where available. Keep source images, context and final compositions distinguishable. Never edit UI pixels to imply a working feature or fix a layout only inside marketing artwork. Use generated imagery for permitted content/backgrounds, not as evidence that the actual app ran.

## Readiness questions

- Is the selected app/build/source identity unambiguous, and are the essential flows complete?
- Do metadata, screenshots and release notes describe that build truthfully?
- Are support/privacy URLs and review access/instructions valid for the requested app?
- Are permissions, privacy/data-safety and audience declarations based on the actual app and integrated services?
- Are the relevant localized assets and provider-required fields complete?
- Is the chosen audience/release mechanism consistent with the user's authorization?

Fetch current Apple/Google documentation for exact dimensions, text limits, account eligibility, billing and review rules. Do not turn a remembered number or old checklist into a current requirement. Store-specific requirements can depend on account, category, territory and features.

## Material handoff

Provide proposed copy and concrete reviewed assets before requesting any missing publication authorization. Explain unresolved factual questions without fabricating answers. Keep marketing files in the selected project output location and out of unrelated repositories.

A technically valid screenshot size is not evidence of a legible composition. A local render is not evidence of the distributed binary. Preserve those distinctions in the release report.
