# Google Play

## Readiness and internal delivery

Use google_play_status to inspect the current account, connection, app identity and saved signing readiness. google_play_app_status reads the requested tracks. The highest observed version code is not a complete history or a guarantee a new code is unused.

Read the exact saved source and revision. When exposed, google_play_prepare_current_project binds that source, connection, signing organization and supported Release AAB/internal destination. It does not save, migrate or bump the project. Inspect the summary and use google_play_publish_current_project only for the already authorized effect with the exact confirmation.

Read the original job with google_play_get_upload. A Debug APK from android_build operations is a different artifact/contract and does not establish a signed Release AAB or a Play delivery. Preserve uncertainty and reconcile the original upload before another start.

## Production review of an existing upload

Where supported, google_play_prepare_production_review prepares a completed owned internal upload with release notes and the current production snapshot. Follow the discovered contract's explicit Managed publishing confirmation. If the provider API cannot verify the setting, obtain the required factual owner confirmation; never infer it from a previous release.

Consume the exact plan with google_play_submit_production_review only when the user has authorized review submission. Poll google_play_get_production_review with its original review ID. A lost submission response is not permission to resubmit.

Interpret inReview, approvedNotPublished and publishedUnexpectedly according to the actual returned contract. A held review acceptance is not a public launch; an unexpected publication is a publication-hold violation to report, not a successful held release. Do not assume these review tools provide a public-launch action.

## Policies, tests and declarations

Fetch current official requirements for the developer account and app category rather than embedding fixed testing quotas, SDK deadlines or review times. Check the actual store listing, app access, permissions, audience, content rating, privacy/data-safety answers and applicable testing eligibility. Obtain factual declarations from the owner; do not invent collection practices.

Use [Google Play's policy center](https://play.google.com/about/developer-content-policy/), [publishing status](https://support.google.com/googleplay/android-developer/answer/9859751), and [managed publishing guidance](https://support.google.com/googleplay/android-developer/answer/9859654).

## Halting a release

For an explicitly authorized halt, use the discovered prepare/halt/status contract for the exact package, track and release. Preserve other releases and the provider-validated serving fallback. A halt does not uninstall existing copies. On an uncertain commit, read the same operation instead of preparing a second edit.
