# Installation

## Standalone skills

Install skills/appmost and optionally skills/appmost-release using your agent host's Agent Skills installer. Install each complete directory, including references and agents metadata. Do not install the repository root as a skill, and do not copy only SKILL.md.

For Codex, use the installer prompts in README.md. Private-repository installation uses your existing authenticated GitHub access. Never put a token in a skill, Git URL, shell history or configuration committed to this repository. If access fails, resolve the account permission through the supported GitHub login flow.

For repository-scoped Codex use, place each skill directory under the target project's `.agents/skills/`. User-wide discovery is available under `~/.agents/skills/`; the built-in installer may manage its own supported installation directory. Follow the installed client's documentation instead of writing global configuration from a skill. Avoid installing the same skill through both standalone and plugin routes.

For a local test, the ZIPs produced by scripts/package.py contain one top-level skill directory each. Extract them with your host's supported process into a chosen test project. The ZIPs are skill artifacts, not plugin submission bundles.

## MCP connection

Use the setup instructions generated by your installed Appmost app, under its External Agents settings. Keep the connection and credentials in the agent host's supported secret/configuration storage. The skills do not hard-code a loopback port, a token or a cloud gateway.

Start the intended Appmost host and rediscover its tool catalog. A stored connection or a static authoring capability list does not establish that a particular runtime tool is available. Check the returned host identity before touching a document. A client that cached an older catalog may need a new connection or chat.

Local Appmost tools can work with an open document and app-owned native rendering. Hosted tools operate on supplied payloads and may expose web-only rendering. Appmost Design has different capabilities and entitlement boundaries. Do not substitute one host's workflow for another.

## Optional plugin distribution

This repo also contains a portable Agent Plugins manifest at plugin.json and a repository marketplace at `.agents/plugins/marketplace.json`. It packages the two skill directories without an MCP server, hooks or an automatic setup script.

Supported Codex clients can add this GitHub marketplace using:

```sh
codex plugin marketplace add appmost/appmost-skills --ref main
```

For local authoring, use the absolute path to this clone instead of the GitHub shorthand. The catalog resolves its plugin from the repository root. Complete installation using the plugin interface supported by your current client; adding a marketplace alone is not installation or authentication.

For reproducible adoption, use a reviewed tag or commit with your client's supported ref selector. No public tag or plugin-directory submission is created by this initial repository. Public directory distribution and any change to repository visibility require an owner decision.

Sources: [OpenAI skills](https://developers.openai.com/codex/skills), [plugin packaging](https://developers.openai.com/plugins/build/plugins), [Agent Skills specification](https://agentskills.io/specification).
